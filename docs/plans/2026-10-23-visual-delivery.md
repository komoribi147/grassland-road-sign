# 第一轮：画面一致性与图片交付

用户已确认实施上一轮建议中的第一轮。本轮不改人物评价、AI 对话或教育回望内容。

## 目标与实现

1. 保留 `assets/stills/*.png` 高清原图；生成带内容指纹的 WebP 网页图和 960px 小图。统一映射供舞台、背景和回望封面使用，避免改动剧情步号、玩家选择和存档内容。
2. 正式发布包只包含网页图、声音及动态样张需要的素材，不再打包高清原图及早期背景。
3. 竖屏保留完整镜头，在画面上部呈现横向原构图；用同一张图的暗色背景衬底。限制对话区高度并允许滚动，避免遮挡人脸和关键动作。横屏维持原有表现。
4. 打开时先检查最新剧本，失败才使用本地缓存；加载下一镜头期间收起上一张清晰画面，防止旧图与新描述并存。
5. 预取改为统一队列与有限前瞻，优先当前镜头，避免两幕图片同时争抢带宽。
6. 逐幕核对图片引用与接续关系，生成可追溯的镜头清单和桌面/手机审阅页；单文件打包同步兼容。

## 验证

- 图片映射覆盖所有正式引用，WebP 可解码，尺寸比例一致，内容指纹正确；对比压缩前后总量。
- 聚焦测试：竖屏完整取景、小图选择与横屏升级、最新剧本优先与离线回退、慢图不得停留上一镜头、统一队列不重复预取。
- 运行剧情、视觉素材、引擎、回望及 AI 既有检查，完成静态与单文件打包。
- 浏览器检查开场、救援、尾声与手机布局；如浏览器连接受限，明确记录限制。
- 同步 GitHub 与腾讯云后，通过无缓存请求比对线上入口、模块与网页图片，逐一检查引用资源。

## 工作区

直接在现有项目中实施；保留未跟踪的 `docs/_pov-audit.html`。输出审阅资料放在父目录 `output/`，不提交无关文件。
