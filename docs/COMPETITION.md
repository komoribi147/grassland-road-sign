# 参赛方案：历史情境探究（AI + 教育）

## 作品定位

《草地上的路标》由历史情境叙事与“路标与证据”探究活动组成。以长征主题历史活动课为首个试用场景，支持学生走近人物处境，区分艺术创作与历史信息，并用有来源的资料修改自己的解释。

目前已实现一个完整的探究样例；尚未完成真实课堂试用，不能声称已经提高学习成绩或证明普遍教学效果。

## 五项重点如何落到产品

| 审查重点 | 当前实现 | 后续证据 |
| --- | --- | --- |
| 明确对象与学习困难 | 首页和探究页标明初中历史长征活动课；练习区分创作、对应依据、解释处境 | 教师审阅与需求验证 |
| AI 提供学习支持 | 自选三类困惑；依据服务器史料提供差异化引导、回应与追问 | 实际反馈质量与教师观察 |
| 保留理解变化 | 锁定初稿与判断；另写修订、依据说明及修改理由；并列展示、下载 | 匿名前后成果 |
| 史料连接剧情 | 在探路棍/红布相关位置给可收起入口；从资料卡进入探究并可返回故事进度 | 课堂使用过程与操作困难 |
| 支持真实试用 | 教师本地导入、去重、人工观察、误解记录与报告备份 | 需要实际招募学生与教师后收集，当前不填虚构结论 |

## 拟解决的学习问题

历史故事能吸引学生，但感动、记住剧情和能够依据史料解释历史是不同的结果。本作品针对“把情境画面当作史实、表达观点时缺少依据、把缺少证据理解为从未发生”这三类需要在试用中验证的学习困难，提供具体的资料比较与修订过程。这些是设计假设，不冒充已完成的用户调研结论。

## 学习过程与 AI 作用

| 环节 | 学生做什么 | 系统提供什么 | 留下什么证据 |
| --- | --- | --- | --- |
| 进入情境 | 体验故事或阅读片段 | 艺术创作边界提示 | 对情境的初步理解 |
| 初始表达 | 写解释、说明判断 | 开放表达，不设统一感受 | 原始解释与判断 |
| 对照资料 | 阅读并选择相关资料 | 带原始来源链接的整理卡 | 选中的资料 |
| AI 阅读建议（可选） | 请助手核对依据 | 结合实际回答回应、提示证据边界、提出追问 | 反馈及所据资料 ID |
| 修改表达 | 自己重新解释 | 保留原稿，避免模型代写 | 修改稿与判断变化 |
| 修订反馈（可选） | 请助手再看独立修订 | 对照两次表达、依据与理由，回应修订并留下后续追问 | 独立保存的修订稿反馈与原话依据 |
| 教师交流 | 讨论依据及未知部分 | 前后并列和文本下载 | 可供教师观察的探究记录 |

AI 的增量是针对学生自己的表达提供学习支持，不以角色说话生动、生成图片或完成配音作为教育效果的证明。无 AI 时仍有明确标注的人工资料提示，支持完成同一活动。

## 技术与可信边界

- 前端：HTML、CSS、原生 JavaScript，零第三方运行依赖。探究记录保存在当前浏览器，与故事存档分开。
- 剧情：JSON 驱动的分支、人物称呼与独立对话记忆。既有预选台词，也允许自由输入；不是所有台词都由学生原创。
- 角色：三位主要 NPC 的人格、上下文与记忆分别组织；不把它宣传成训练了三个独立模型。
- 模型：兼容讯飞星火、DeepSeek 等 OpenAI 兼容接口，以及本地 Ollama。2026-10-25 审查时公网角色对话实际使用 deepseek-chat；本地环境与公网配置应分别标注，不能以仓库默认值冒充实际运行模型。
- 探究接口：单独的 `/api/inquiry`。服务端核对模型回应的原话是否来自学生初稿，再从固定证据 ID 恢复资料整理摘录和支持范围；不采用模型或浏览器自造的引文。原话或依据不合要求时在同一总时限内最多重新生成一次，仍不合要求就明确失败。该检查不能保证模型解释的推理正确，建议仍需教师核对。
- 教师记录：`teacher-review.html` 在本地导入匿名成果，人工观察三项学习表现，记录常见误解和课堂可用性；不把学生选项或模型反馈自动转成成绩。
- 教师核查：展示 AI 实际反馈、对应原句、固定资料摘录、完整整理卡与来源入口。教师独立记录 AI 建议是否有帮助或需要纠正，核查备注随报告导出。旧反馈缺少逐句依据时明确标注，不补造。
- 两阶段反馈：初稿与修订稿使用不同请求快照和记录字段。修订反馈同时读取初稿、修订、学生依据与修改理由，原话核对针对修订稿；修改相关内容后旧建议失效。教师分别核查两次建议，旧记录仍可导入。两阶段都由学生选择是否使用，不自动判断学习进步。
- 内容：史实背景来自人工整理的资料卡，人物与具体遭遇为艺术创作；资料卡不是原文引用。
- 失败：AI 未返回时明确提示；人工提示不冒充模型回复，失败回复不记入成果。
- 配音：固定剧情配音与实时生成语音是不同功能；当前公开站点的实时回复语音尚未开通，本地模型能力需要现场单独验证。
- 数据：不要求姓名、班级或账号；发送 AI 请求前提示发送内容。不用字数、情绪、角色信任值评价品德或学习水平。

## 六分钟展示建议

1. **0:00–0:45** 说明试用对象与具体学习问题，展示故事如何进入情境。
2. **0:45–1:30** 在探究页写一条真实初始解释，说明如何保留学生原话。
3. **1:30–2:30** 对照资料卡，区分剧中红布路标、史料整理与可继续阅读的来源。
4. **2:30–3:45** 请 AI 回应这条解释，展示它指出的依据与追问。若断线，明确展示人工资料提示。
5. **3:45–4:45** 学生自己修改，展示前后对照与来源下载，说明不以同意 AI 为目标。
6. **4:45–6:00** 说明已有功能验证、真实课堂试用计划、失败案例与推广边界。

备份使用录屏并注明录制条件与模型；不要把录屏描述成现场实时回答。

## 验证与待完成事项

自动化检查覆盖剧情、存档、音画、AI 错误处理、探究草稿恢复、反馈来源校验与 API 输入边界；实际检查结果应随交付版本记录。自动测试通过不证明学习效果。

下一步需邀请教师审阅材料与活动安排，组织小规模匿名试用，观察学生能否区分创作与史实、引用依据和修订解释。教师活动单见 `TEACHING_ACTIVITY.md`。多人访问容量、设备差异及课堂效果均需另行验证。
